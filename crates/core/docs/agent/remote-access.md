# Remote access: walking the user through it
Remote access lets the user's devices reach their Tessera server away from home (mobile data, work). The user sets it up themselves in **Settings → Connection → Away from home** (any app) or with `tessera setup devices` on the server; you can't do it for them (network settings are the user's; `tessera remote`, `tessera pair` and the like are refused for you). Your job: guide them one step at a time in plain words, check what you can, and fix problems. Their own copy of this guide: Settings → Help & tour → Guides → "Reaching Tessera from anywhere".

## How to guide
- One step per message: say what they'll see and exactly what to click, then wait for "done" (or what they see instead) before the next step. Explain a new word the first time (domain, tunnel, API token, Cloudflare Access, Zero Trust). No jargon, no walls of text.
- First find out: what runs the server (you know: this machine's OS and name), whether they already use Cloudflare or own a domain, and which device they'll test from. Ask if it's set up already: Settings → Connection says "Reachable from anywhere" with the address, or "Only at home for now".
- Recommend **Cloudflare** (free account, a domain at about $10 a year, phones need nothing extra). Without a domain and unwilling to buy one: **Tailscale** (free; the Tailscale app on the server and every device). Their own reverse proxy only if they already run one. Tessera doesn't offer Cloudflare's "quick tunnels" (the address changes on every restart, no door in front).
- The Cloudflare steps happen in their own web browser, not in a web view you control: the API token would show up in what you read. Never ask for the token in the chat; it goes only into the token field in Settings → Connection (or `tessera setup devices`). If they paste one in the chat anyway, don't repeat or use it, and suggest deleting it in Cloudflare and making a new one.
- Windows server: the same steps in the app; the PC must stay on and not sleep. Windows specifics: the guide "Tessera on Windows".

## Cloudflare, step by step (about 15 minutes)
1. **Account**: sign up at dash.cloudflare.com/sign-up and confirm the email. Suggest two-step sign-in (My Profile → Authentication).
2. **Domain**: buy one in the dashboard under Domain registration → Register domains (search, Purchase, contact details, Complete purchase; confirm the email Cloudflare sends or the domain gets suspended). A domain bought elsewhere: Add (Onboard) a domain → Free plan → put Cloudflare's two nameservers at the registrar → wait until the domain shows **Active** (minutes to a day).
3. **Zero Trust (free)**, once per account: dashboard → Zero Trust (one.dash.cloudflare.com) → pick any team name → Free plan → checkout (asks for payment details, charges nothing). Skip if they already have it. Forgotten: "Check token" in Tessera says "Turn on Zero Trust first" (with Open Zero Trust and Check again) before anything is created.
4. **API token**: dash.cloudflare.com/profile/api-tokens → Create Token → Create Custom Token: Get started. Name `Tessera`. Five permission rows (+ Add more): Account · Cloudflare Tunnel · Edit; Account · Access: Apps and Policies · Edit; Account · Access: Service Tokens · Edit; Zone · DNS · Edit; Zone · Zone · Read. Account Resources: Include → their account. Zone Resources: Include → Specific zone → the domain. Optional TTL ending tomorrow. Continue to summary → Create Token → Copy (shown once).
5. **In Tessera**: Settings → Connection → Away from home → Set it up with Cloudflare → paste → Check token → pick the domain, keep `tessera.<domain>` → Set up remote access. Progress shows each step; done when it says "Remote access is ready" and "Cloudflare tunnel connected". Terminal: `tessera setup devices` → At home and away → Cloudflare Tunnel (automatic).
6. **Delete the token** in Cloudflare (My Profile → API Tokens → ⋯ → Delete); Tessera didn't keep it.
7. **Devices pick it up by themselves**: no pairing again. Devices paired before learn the new address and Access key over their encrypted connection: open Tessera on each once while it's at home (or can still reach the server). The phone's Settings → Connection then lists the `https://` address with a cloud icon. Devices paired later get it in their code. (A phone app too old for this: update it, or pair again; pairing again replaces its entry, no duplicate.)
8. **Test**: Wi-Fi off on the phone, open Tessera, send a message. Settings → Connection shows the `https://` address with a cloud icon marked "in use". Wi-Fi back on.

What it creates in their Cloudflare account (don't let them delete these by hand; "Remove remote access" does it): tunnel `tessera-…`, a DNS record "Tessera tunnel", Access application "Tessera (<address>)", service token "Tessera apps (<address>)" valid one year (Tessera reminds them from 30 days before: a notification and a Renew line in Settings → Connection), and with web browsers on, an Access application for `<address>/web`. Safety in one breath: no ports opened at home (the tunnel goes out), Cloudflare Access lets only their paired apps through, and everything is end-to-end encrypted, so Cloudflare can't read it.

## Checks you can run (read-only)
- `curl -sS -o /dev/null -w '%{http_code} %{redirect_url}\n' https://<address>/api/health`: a 302 to `cloudflareaccess.com` or a 403 means the address and the Access door work (Access stops you, as it should; it answers before the tunnel, so this says nothing about the tunnel). "Could not resolve host": the DNS record is missing or the domain isn't active. Whether the tunnel is connected: the tunnel line in Settings → Connection (the user reads it to you).
- Outbound tunnel port: `timeout 5 bash -c '</dev/tcp/region1.v2.argotunnel.com/7844' && echo open` (Linux; on Windows `Test-NetConnection region1.v2.argotunnel.com -Port 7844`).
- Whether cloudflared runs on the server: `pgrep -a cloudflared` (Linux) or `Get-Process cloudflared` (Windows).

## Problems and fixes
- "This token can't see any domain": Zone Resources lack the domain, or the domain isn't Active yet.
- "Turn on Zero Trust first" (or the setup stopped at Access): Zero Trust isn't on (step 3), then "Check again"; if it is on, the token lacks Access: Apps and Policies · Edit or Access: Service Tokens · Edit.
- "Cloudflare refused … Check the token has the permissions": a permission is missing or Read instead of Edit; make a new token row by row.
- "… is already in use in your DNS" / "an Access application already protects …": pick another name (`tessera2.<domain>`).
- Tunnel not connected, port 7844: a firewall blocks outgoing TCP/UDP 7844 to region1/region2.v2.argotunnel.com; allow it (ufw: `sudo ufw allow out 7844`, the user runs it), then "Check again". If the network can't change: Tailscale.
- Works on Wi-Fi, not on mobile data: the device hasn't connected since setup (open the app once at home, step 7), the tunnel is down, the key ran out (renew), or the server is off or asleep.
- A browser shows a Cloudflare page at the address: expected (only the apps carry the key). For browsers: Settings → Connection → Web browsers → Use Tessera in a web browser (asks once for a token with Account · Access: Apps and Policies · Edit), then open `https://<address>/web/`.
- Renewing the key (yearly; reminded from 30 days before, "Remote access stopped" once expired): Settings → Connection → Renew → a token with one permission, Account · Access: Service Tokens · Edit (used once, never stored) → Renew. Or in Cloudflare: Zero Trust → Access controls → Service credentials → Service Tokens → "Tessera apps (…)" → Refresh, then Renew → "Or renew it in Cloudflare yourself" → "I renewed it". The same key gets another year: devices need nothing. A setup from before Tessera kept the date shows "Renew it once".

## Tailscale and turning it off
- **Tailscale**: install it on the server (Linux: `curl -fsSL https://tailscale.com/install.sh | sh` then `sudo tailscale up`, both run by the user; Windows/macOS: tailscale.com/download) and on each device, same account. Settings → Connection: turn on "Let other devices on my network connect", then "I use Tailscale or my own tunnel" → the server's Tailscale address (e.g. `http://my-server.tail1234.ts.net:7878`) → Save; paired devices pick it up (open the app once at home). Tailscale must stay on on the phone.
- **Turn off (Cloudflare)**: a new token with the same five permissions → Settings → Connection → Remove remote access → paste → Remove. It deletes the tunnel, DNS record, Access applications and service token; devices then work at home only. The domain and account stay theirs.
- **Turn off (Tailscale or own address)**: "I use Tailscale or my own tunnel" → remove the address (✕) → Save; devices forget it by themselves.

# Claude through the user's own Claude Code
Provider `claude-code` ("Claude (your subscription)") runs a chat's turns in the user's own Claude Code CLI, so they use the user's Claude Pro/Max plan. Tessera never signs in to Claude.ai (Anthropic doesn't allow other apps to) and never reads Claude Code's credentials or settings: it runs the unmodified `claude` the user installed and signed in to, headless (`claude -p`, stream-json, documented flags only), on the server. Each user signs in with their own plan; Tessera never shares or resells one.

**Setting it up** (guide the user; you can't do the sign-in for them): install Claude Code on the server machine (https://code.claude.com/docs/en/setup), run `claude` once in a terminal there as the user Tessera runs as and sign in, then press Check again in Settings → Models → Your Claude plan (or `tessera setup models`; `tessera add-provider claude-code --kind claude-code`; `tessera login claude` prints the next step). Then pick a model such as `claude-code/sonnet`. Nothing else to configure: Tessera's tools and context come with every turn. `claude auth status` tells whether it's signed in. If the server doesn't find `claude` (a service's PATH), the user names it in `config.toml`: `[[provider]] id = "claude-code"`, `kind = "claude_code"`, `base_url = "/path/to/claude"`. Alternative: an Anthropic API key (provider kind `anthropic`, billed per token).

**Tessera's tools**: the Agent SDK's in-process MCP server relays stdin/stdout calls to this chat's normal dispatch, approval and scope checks (no port/token; ends with the turn). Tools include native read/write/edit/grep/glob/web_fetch, helpers (`agent` starts, `agents` manages), browser, machines, notes, memory, jobs and bot hand-offs as the tool preset allows. Prefer bridged bash/job for commands, output, Stop and scoped `$NAME` injection; CLI task ids differ. Cards and approvals stay in Tessera. Stable appended context includes memory/profile, bot instructions/knowledge/contacts, secret names, user/project instructions and skills; changes arrive at turn boundaries/compaction. Restricted presets limit CLI built-ins and external MCP too. Private chats expose only selected public search, never local context/history. CLI children cannot delegate. Main hand-offs need exact hook id/tool/input, main actor and affirmative admission; an open card is not authority.

**How a turn runs**: in the chat's folder, inside Tessera's command sandbox (Tessera's data and secrets hidden; `~/.claude` and the network reachable), continuing Claude Code's own conversation (`--resume`; each bot in a channel has its own). Its permission prompts become Tessera approvals: Default mode → Claude Code `acceptEdits`, unusual commands and anything else it asks about need approval; Ask → everything it asks about; Read-only → plan mode, nothing changes; YOLO → allowed without asking (commands Tessera refuses stay refused; its checks are never bypassed). Its own subagents (Task/Agent) show as a subagent card with steps and time.

**Without another model**: Haiku titles and memory reviews use the plan; channels/DMs use each bot's account. A watched chat stops on plan exhaustion; eligible unattended work waits within one total six-hour/three-retry budget. Stop cancels; notifications deduplicate by chat/account/reset, even after restart, with device-local reset times. No reported reset means no guessed wait. Compact uses `/compact`; rewind restores CLI edit snapshots, not shell side effects. Task lists share Tessera's ledger. Changed code gets one verification nudge. Fast mode spends credits. Warm CLI processes (default10min) skip startup; autonomous continuations retain approvals, tools, Stop and checks. Usage shows reported tokens/API-equivalent cost, not a plan bill. Guide: docs/CLAUDE_CODE.md.

The bridge includes enabled `lsp` and configured external MCP under normal policy. Configured Tessera `web_search` replaces CLI WebSearch; otherwise CLI search stays. CLI Read/Write/Edit/MultiEdit/Grep/Glob/WebFetch remain alternatives with different semantics. Use native scanned project guidance and bridged `skill`, never Claude folders.

`save_secret` requests secure UI entry using metadata alone. Never put values in arguments; never collect Claude sign-in. The user types values into Tessera's password inputs. Card-only saving keeps the safe resume link and warm process; updated credential names arrive as turn context. Only if earlier values are found in the transcript does the warning say plaintext stays in Claude's history (never edited by Tessera), with the next turn starting from sanitized Tessera history. Settings/tool-schema changes refresh the appended context and bridge only at a turn boundary, never mid-turn; unchanged turns keep the warm process.

Claude Code auto-memory is off for Tessera-launched child processes via the documented `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` environment switch. Use Tessera's `memory` tool for persistence; never attempt to write `~/.claude/projects/.../memory/` or any `~/.claude*` path. This does not modify the user's saved CLI settings. CLI cron/wake-up tools remain session-only, not durable Tessera jobs; prefer `schedule` for persistent work.
